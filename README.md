# 読解力ラボ

高校生向けの読解力トレーニング用Webアプリです。HTML / CSS / バニラJavaScriptによる静的構成で、インストールやビルドは不要です。教材は独自作成の試作70問（7分野各10問）で、公式RSTではありません。

## ローカル起動

このリポジトリのディレクトリで次を実行してください（Python 3）。

```sh
python3 -m http.server 8000
```

`http://localhost:8000/` を開きます。`file://` では問題の読み込みが失敗するため、HTTPサーバーを使ってください。Node.jsがある場合は `npm run dev` でも起動できます。依存パッケージはありません。

## 使い方

- 分野別：7分野から選択し、5問／10問／全問と未挑戦優先を設定します。対象が少なければ出題数を減らします。
- ランダム：全分野から重複なしで出題します。選択肢順は固定です。
- 解答：4択を選んで「解答する」を押すと確定します。正誤、正解、解説、着眼点を読み、次へ進みます。
- 結果：今回の正答率と誤答の解説を確認できます。
- 間違い直し：現在の問題版に対する最新解答が誤答の問題が対象です。正解すると復習待ちから外れます。
- リセット：ホーム下部から、確認ダイアログを経て学習履歴を削除できます。

学習履歴は `reading-skill-lab:progress:v1` に保存されます。氏名などの個人情報は収集せず、ログインや外部送信はありません。履歴は端末・ブラウザー間で同期しません。保存無効や壊れた履歴では警告を表示し、画面を開いている間は一時学習できます。壊れた保存記録は自動上書きせず、必要ならリセットしてください。

## 学習分析 Ver.1.1

ホームの「学習レポート」から、全体と7分野ごとの初回正答率・最新正答率・学習済み問題数を確認できます。各分野の「この分野を練習する」から演習に進めます。PCは分野カードを2列、スマートフォンは1列で表示します。

- 初回正答率：各問題で最初に記録された解答の正答率です。
- 最新正答率：各問題で最後に記録された解答の正答率です。復習後の理解を確認できます。
- 学習進捗：現在の70問のうち、一度でも解答した問題数です。

現在の問題IDとversionに一致する履歴だけを、保存された配列順で集計します。日時による並べ替えは行いません。未挑戦問題は正答率の分母に含めず、解答がない場合は「—」と表示します。正答率は整数に四捨五入します。既存の累計正答率は全解答回数に基づく従来の指標としてホームに残しています。

集計は画面を開くたびに既存履歴から計算します。保存キー・保存形式・履歴を変更せず、分析用の追加保存データや移行操作は不要です。

## 70問への更新と学習履歴

既存14問の内容・ID・versionは変更していません。保存キーと `id@version` の紐づけも維持しており、同じ端末・ブラウザー・サイトでは既存の学習履歴がそのまま使えます。新規56問は未挑戦として扱われます。履歴のリセットや移行操作は不要です。70問すべて試作問題のため、授業配布前の内容レビューをお願いします。

## 構成と問題の更新

| ファイル | 内容 |
| --- | --- |
| `index.html`, `styles.css` | 日本語UI、スマートフォン対応、キーボード操作・フォーカス表示 |
| `app.js` | 画面遷移、問題表示・採点・結果 |
| `quiz.js` | 問題データ検証、出題順、問題版キー |
| `analytics.js` | 履歴を変更しない初回・最新・分野別集計 |
| `progress.js` | 保存処理を分離したProgressRepository |
| `data/questions.json` | `questions.all70.review.json` の変更なしコピー（既存14問も保持） |
| `tests/` | 出題・保存の自動テスト、サブパス配信確認 |
| `scripts/serve.py`, `package.json` | 任意の開発サーバーとテストコマンド |

通常は `data/questions.json` を更新して問題を追加します。IDは保持し、内容や正答の変更時にはversionを増やしてください。`draft` は出題せず、`pilot` は「試作問題」と表示します。問題数やカテゴリーはJSONから取得します。問題・答えはブラウザーに配信されます。試験監督用のシステムではありません。

## GitHub Pagesへの公開手順（管理者によるレビュー後）

1. 変更内容をレビューし、管理者が公開対象ブランチへ反映します。
2. GitHubの Settings → Pages → Build and deployment で「Deploy from a branch」を選択します。
3. 公開対象ブランチ（例：main）と `/(root)` を指定して保存します。
4. `https://ユーザー名.github.io/リポジトリ名/` を開いて動作を確認します。

すべてのアセット・JSON取得は相対パスです。サブパス用のビルド設定やSPAフォールバックは不要です。この実装作業ではマージ・公開は行っていません。
